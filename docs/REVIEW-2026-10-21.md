# Independent review of ucraya.uk, 21 October 2026

Reviewer: Opus 5.5, read only. Scope: the English site in `dist/` built from commit 7dd7120, the three articles, the article engine (`content/ARTICLE-*.md`, `scripts/articles/*`), `netlify.toml`. The Bulgarian, Romanian and Polish JSON files were not reviewed (translation in progress).

## Verdict: FIX FIRST

| Severity | Count |
|---|---|
| Must fix before launch (or before the first scheduled article on 25 Oct) | 7 |
| Should fix | 19 |
| Nice to have | 12 |

What was run: `npm run build` (91 pages, passes), `npm run check` (0 failures), `npm run check:articles` (3 pass, 3 warnings), `node scripts/shots.mjs` with 12 pages (0 horizontal scroll at 375 and 1280), Playwright checks of the form prefill, the placement test flow, h1 counts and the submit button, a crafted bad article run through the checker (then deleted), and the five official URLs from this container (all blocked, as expected).

The site is clean, fast (about 3 KB of JavaScript in total, 27 KB CSS, no images beyond SVG and one OG PNG), honest in tone, and the structure (course pages with price box, form on page, sticky Enquire and WhatsApp bar, placement test into the form) is right for the audience. The blockers are one broken button that stops every enquiry, unverified "checked on" claims in two articles, future publication dates, a free class offer shown on pages where it does not apply, and an article engine that will stall and whose checker would let serious false claims through.

## 1. Must fix

### M1. The enquiry form's submit button is empty on every page (40 forms, all locales)
- File: `src/components/EnquiryForm.astro` line 112: `<button type="submit" class="btn btn-primary">{f.send}</button>`. `send` lives under `buttons`, not `form`, so the button renders as `<button ...></button>`: a 49 px yellow circle with no text and no accessible name (screenshot at 375 px confirms; Playwright reports the name as empty). Visitors will not know how to send; screen readers announce "button".
- Fix: `<button type="submit" class="btn btn-primary">{m.buttons.send}</button>`.
- Guard: add to `scripts/check-site.mjs` a failure for any `<button>` or `<a>` whose text is empty and has no `aria-label`. Add `@astrojs/check` and run `astro check` in the build: the TypeScript type of `m.form` would have caught this.

### M5. The daily article engine stalls for ever on the first row it cannot finish
`scripts/articles/next.mjs` always returns the lowest numbered `planned` row that is due, and ARTICLE-TASK "If something fails" says leave the row `planned`. So one bad row blocks every later row, and one article a day means the backlog never clears. Rows that will fail today: every row that must state a test or immigration rule while gov.uk, nmc.org.uk, trinitycollege.com, ielts.org and oet.com are blocked (nursing 17, B1 18, IELTS 11 rows; day 4 on 25 Oct is the first), any row whose `money_page` is not a known page, and any slug that already exists.
- Fix:
  1. Add an `attempts` column (or reuse `url` as "FAILED n") to the map; `next.mjs` skips rows with status `blocked`; on failure the session runs a new `npm run article:fail <day> "<reason>"` that increments attempts and sets `status=blocked` after 2 failures.
  2. ARTICLE-TASK: when an official page will not load, first try the WebSearch tool or `curl` through the proxy; if still blocked and the row needs the rule, fail the day; if the row can be written without stating the rule (send the reader to the named page), write it that way.
  3. Alert: on any failure or blocked row, also open a GitHub issue titled "Article day N not published" (with `gh issue create`), because nobody reads `content/log.md`.

### M6. The article checker passes an article with serious false claims
I wrote a day 4 article in /tmp (deleted afterwards) and `node scripts/articles/check.mjs` reported PASS for all of this:
- "Ucraya is an approved OET preparation provider recognised by the OET organisation"
- "We run the OET test at our London centre on Saturdays"

The checker is a good format checker but not a truth gate, and the engine publishes with no human. Before 25 Oct add to `scripts/articles/check.mjs`:
- fail on: `/\b(approved|recognised|recognized|endorsed|certified)\b[^.]{0,60}\b(provider|centre|center|by)\b/i`, `/\b(we|ucraya)\s+(run|host|hold|offer|administer)s?\s+(the\s+)?(oet|ielts|selt|b1|gese|test|exam)/i`, `/\btest cent(re|er)\b/i` unless preceded by "a" provider wording you allow, `/\d+\s?%/` (percentages) unless on a line citing a source URL in `sources`, `/\b(assured|definitely|certain to|will pass|success rate|native|years of experience)\b/i`, `/\s-\s|--/` (dash substitutes), `/\b(teams|meet|skype|whatsapp call)\b/i` as a platform claim;
- quotes: fail on any curly or straight quotation of 6 or more words followed or preceded by a capitalised name, unless the text is word for word one of the six FACTS section 6 testimonials;
- money: a pound amount outside PRICE_ALLOW passes only if the URL on that line is also listed in front matter `sources` and the line contains "checked";
- `sources[].checked` must equal today (`todayLondon()`), and an article whose pillar is nursing, B1 or IELTS and that contains a digit next to "score", "band", "fee" or "minutes" must have at least one source;
- acronyms: any token of 2 to 6 capital letters that is not in an allow list (UK, GBP, A1, A2, B1, B2, C1, CV, NHS, PDF) must have a bracketed expansion within 120 characters of its first use.
